
암호화
: 평문을 특정 키를 사용해 해독할 수 없는 형태로 변경하는 것


## 1) 단방향 암호화 

- 평문 -> 암호문 O (암호화 가능)
- 암호문 -> 평문 X (복호화 불가능)

ex ) Hash, SHA2계열(SHA-256), 비밀번호, 인증, 신원 증명, 메시지인증코드(MAC)
[[SHA1 vs SHA2 알고리즘]]

-- 단방향 암호화는, 2개의 다른 메세지가 같은 암호값을 갖는 **충돌(collision)** 이 생기면 끝


## 2) 양방향 암호화

- 평문 <-> 암호문

-- 암호화와 복호화가 같은 키를 사용하는지에 따라 대칭키/비대칭키로 나뉨

대칭키, 비대칭키(공개키, 개인키)
양쪽에서 메세지를 암호화해 수신할 때, 수신 과정에서 스니핑을 당하더라도 위험이 줄어듦


**암호키 종류**
1. **대칭키 / 비공개키**
- 암/복호화에 동일한 키를 사용
- 키(secret key)가 노출되면 안되기에 비공개키라고도 함
> - secret key : 노출 비밀
> - private key : 절대 노출되면 안됨

장점 : 비대칭키에 비해 속도가 빠름
단점 : 키 교환해야하기에 키 배송 문제가 있음 / 키 탈취 가능성 / 관련된 사람이 많아질수록 각자 키를 보관해야하기에 관리할 키의 범위가 넓어짐


ex) AES, DES, 3DES, SEED, ARIA 알고리즘


2. **비대칭키**
- 암/복호화에 다른 키를 사용
- 노출시켜선 안되는 Private key, 노출가능한 Public Key
> - Private Key는 데이터 중요도가 높은 서버에서 사용
> - 클라이언트 측은 Public Key 사용

장점 : 공개키는 오픈되어있어 교환할 필요 없음
단점 : 대칭키 방식에 비해 속도가 느림

ex) RSA 알고리즘
